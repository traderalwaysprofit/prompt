# Frontend Architecture V1 — Current Implementation

**Status:** current-state documentation, updated 28 August 2026.

## 1. Objective

SAMSON Prompt is a static-first prompt explorer for `samson.web.id`. The current runtime contains 197 commands without a frontend framework or backend dependency.

## 2. Runtime architecture

| Concern | Current source of truth |
|---|---|
| HTML entry | `/index.html` |
| Application state, rendering, search, filters, favorites, modal, copy | `/src/main.js` |
| Header enhancement, onboarding, desktop/mobile navigation | `/src/app-shell.js` |
| Core styles | `/src/styles.css` |
| Smart/favorite styles | `/src/level4.css` |
| Compact prompt-card theme | `/src/prompt-card-theme.css` |
| Navigation/onboarding styles | `/src/app-shell.css` |
| Build output | `/dist`, generated by `scripts/build-static.mjs` |
| Deployment | Cloudflare Pages workflow |

The shell is rendered by `main.js`, which emits `samson:shell-ready`. The app-shell controller listens for this targeted event and initializes once. There is no global subtree `MutationObserver`.

## 3. UI structure

- Sticky header: brand, Explore, Recently Used, Favorites, Onboarding AI.
- Mobile navigation: one hamburger button and one panel mirroring the desktop actions.
- Hero: product statement, actions, runtime statistics, Smart Discovery card.
- Prompt library: smart search, category `select`, recommendations/recent prompts, cards, pagination.
- Prompt detail: description, example, reusable prompt, favorite, and copy controls.
- Creator/footer sections.

## 4. Runtime data contract

The browser loads and merges:

- `data/commands.json`: 189 base commands;
- `data/commands-extra.json`: 8 additional commands;
- `data/examples.json` + `data/examples-extra.json`: 197 examples total;
- `data/categories.json`: 19 categories.

A command uses the fields `id`, `name`, `categoryId`, `description`, and `template`. The old `cmd/category` field names are not part of the current contract.
Command IDs 47, 48, 50, and 52 are retired and reserved; validation rejects future reuse.

## 5. Interaction model

1. Render the static application shell.
2. Emit `samson:shell-ready` for targeted enhancement.
3. Load the five JSON data files in parallel.
4. Merge base and extra commands/examples.
5. Validate the expected 197-command/197-example totals.
6. Search and filter locally.
7. Persist favorites and recent commands in `localStorage`.
8. Render explicit offline/error UI when the data pipeline fails.

## 6. Build contract

`npm run build` recreates `dist/` and copies `index.html`, `favicon.svg`, `src/`, and `data/`.

No legacy generated command module or unused visual patch is shipped.

## 7. Validation layers

- `npm run validate:data`: validates the complete 197-command runtime contract, categories, examples, unique IDs, and cross-references.
- Baseline build: verifies static output.
- Browser E2E on push/PR: builds and tests the current branch locally.
- Browser E2E after deployment: tests `samson.web.id`.
- HTTP production validation: checks deployed entry files, favicon, JSON totals, field names, unique IDs, and category references.

## 8. Deferred / future targets

The following are not implemented in V1:

- authentication and user accounts;
- database-backed synchronization;
- AI API execution;
- URL-hash state;
- multi-command composition;
- analytics;
- drag-and-drop workflow builder;
- server-side personalization;
- framework migration (React/Vue/Svelte).
